# 슬롯 인벤토리와 제작

Phase 05, .NET 10. 실제 게임은 슬롯 인벤토리를 사용한다. [검증 기록](validation/phase05/README.md)에 Debug/Release 회귀, 네이티브 UI 및 CPU 측정을 보존했다.

## 슬롯과 수량

`PlayerInventory`의 36칸 중 0–8은 핫바, 9–35는 가방이다. 2×2 개인 제작 입력 4칸, 3×3 제작대 입력 9칸, 마우스로 든 Cursor는 별도다. 각 스택은 영구 `ContentId`와 양의 수량을 갖는다. 등록 시 `ItemDefinition.MaxStack`을 1–1024로 검증하며 기본값은 64다. 실제 슬롯은 등록된 제한을 따른다. 읽기 전용 슬롯 목록을 노출하고 변경은 모델 API를 통한다.

기존 총수량 형식은 36칸보다 훨씬 많은 재료를 갖고 있다. 이행 시 설정의 핫바를 우선해 각 스택을 배치하고 남은 수량은 Reserve에 보존한다. 새 게임도 기존 시작 재료의 총수량을 유지하며 가방 27칸을 비워 둔다. 블록 라이브러리에서 소유한 스택을 핫바로 이동하거나 보관함에서 꺼낼 수 있다. 슬롯이 가득 차 있고 교체할 재료가 보관함에만 있다면 공간을 먼저 확보해야 한다. 이행·자동 부품 회수의 초과분 보존이 목적이며, 일반 광질을 무제한 보관함으로 보내지는 않는다.

일반 채굴은 광물과 함께 떨어져 나갈 전선/레버까지 담을 수 있는지 먼저 확인한다. 공간이 없으면 블록을 파괴하지 않는다. 설치는 실제 선택 핫바 슬롯에서 하나를 소비한다. 제작 재료·커서·보관함에 있는 수량만으로 설치할 수는 없다. 가운데 클릭과 라이브러리 선택은 소유한 재료를 이동하며 수량을 만들지 않는다.

## 조작

| 입력 | 동작 |
|---|---|
| E | 개인 인벤토리와 2×2 제작창 열기/닫기 |
| 제작대 우클릭 | 가까운 제작대의 3×3 제작창 열기. Shift 우클릭은 기존 설치 동작 |
| 왼쪽 클릭 | 스택 들기, 합치기, 다른 스택과 교환 |
| 오른쪽 클릭 | 절반 들기, 하나 놓기 |
| 왼쪽 드래그 | 방문한 호환 슬롯에 균등 분배 |
| 오른쪽 드래그 | 방문한 슬롯마다 하나씩 놓기 |
| Shift 클릭 | 핫바 ↔ 가방, 제작 입력 → 소지 슬롯 이동 |
| 결과 클릭 | 결과를 커서에 받고 재료 소비 |
| Shift 결과 클릭 | 공간과 재료가 허용하는 만큼 소지 슬롯으로 제작 |
| Q / Ctrl+Q | 하나 / 전체 스택 버리기. 창에서는 커서 또는 가리킨 슬롯을 사용 |
| LIBRARY / INVENTORY | 기존 검색·분류 블록 라이브러리와 슬롯 화면 전환 |

프레임의 마우스 상태는 `InventoryGesture`에 슬롯 식별자로 전달한다. 같은 슬롯을 중복 방문해도 한 번만 분배한다. 창/월드 전환 시 진행 중 제스처를 취소하며, 이미 든 아이템은 커서에 남는다. 제작 입력과 커서는 창을 닫아도 보존되고 저장된다. 다른 제작대를 열면 같은 개인 3×3 입력을 다시 사용할 수 있다.

## 제작과 JSON

`Assets/recipes.json`은 빌드·publish 출력에 복사된다. 기본 34개 레시피는 8종 원목 → 판자, 8종 판자 → 막대·제작대, 광석 블록 압축/해제 4쌍, 석재 벽돌·사암이다. 현재 게임의 블록 재료를 사용하는 프로토타입 레시피이며 제련이나 도구 내구도를 추가하지 않는다.

`RecipeBook.LoadJson`은 이름 중복, 미등록 재료/결과, 잘못된 크기·키·수량을 거부한다. 파일은 최대 1MiB, 레시피는 최대 4096개다. shaped는 1–3행/열 패턴을 공백 정리한 뒤 이동·좌우 반전해서 비교하고, shapeless는 같은 재료가 여러 번 필요한 경우까지 정확한 다중집합으로 비교한다. 레시피 바깥의 추가 입력은 허용하지 않는다. 태그·대체 재료·제련 레시피·런타임 파일 감시는 아직 없다.

```json
[
  {
    "id": "example:stone_square",
    "type": "shaped",
    "pattern": ["SS", "SS"],
    "key": { "S": "blockcircuit:stone" },
    "result": { "item": "blockcircuit:stone_bricks", "count": 4 }
  },
  {
    "id": "example:oak_planks",
    "type": "shapeless",
    "ingredients": ["blockcircuit:oak_log"],
    "result": { "item": "blockcircuit:oak_planks", "count": 4 }
  }
]
```

미리보기는 수량을 바꾸지 않는다. 결과를 받을 때 입력을 다시 조회하고 분리된 후보 인벤토리에서 재료 차감과 출력 공간을 검증한 뒤 한 번에 반영한다. 결과 커서가 다른 재료를 들고 있거나 목적지가 가득 차면 재료를 소비하지 않는다. 반복 제작은 요청당 최대 1024회로 제한한다.

## 버리기와 저장

버린 아이템은 GUID·문자열 ID·수량·위치·줍기 가능 틱을 가진 제한된 월드 pickup이다. 최대 4096개이며, 생성 실패 시 소지품을 차감하지 않는다. 게임의 20 TPS 경로에서 20틱 후 1.5블록 이내 접근하면 소지 공간을 확인해 한 번만 회수한다. 공간이 없거나 모드가 누락되었으면 그대로 보존한다. 언로드된 열에서는 회수하지 않는다.

이 단계의 pickup은 작은 색상 큐브로 표시하는 정지된 레코드다. 중력·투척 궤적·월드 충돌·자동 소멸·일반 엔티티 엔진은 Phase 09 범위로 남겼다. 보관 중인 제작 재료나 버린 아이템을 임의로 삭제하는 타이머는 없다.

v3 portable snapshot과 v4 매니페스트에 선택적 `ItemInventory`를 추가한다. Player는 Slots/Craft2/Craft3/Cursor/Reserve, Drops는 월드 pickup 배열이다. 기존 `Counts`는 슬롯·입력·커서·보관함의 총합을 유지하며 아직 줍지 않은 Drops를 포함하지 않는다. 두 표현이 다르면 로드 전에 거부한다. 배열 크기·스택 한도·좌표·수량·중복 GUID를 검증한 뒤 활성 월드를 교체한다. 기존 v1/v2/v3/v4는 계속 읽으며, 원래 180칸인 v2도 제작대가 추가된 이후 읽을 수 있다. 첫 v4 슬롯 저장은 기존 파일을 `backups/*-legacy-v4-*.json`으로 별도 보존하며 참조 청크도 해당 백업의 .chunks 폴더에 복사한다.

알 수 없는 아이템은 ID와 수량 및 슬롯 위치를 보존한다. 모드가 없을 때는 제작·설치·버리기에 사용하지 않으며 복구 후 원래 아이템으로 사용할 수 있다. 등록된 아이템의 제한을 넘긴 저장은 거부하고, 누락된 아이템은 등록 API 최대치인 1024까지 보존한다.

기존 `World.Inventory` 배열은 호환용 총수량 뷰다. 실제 슬롯 모드에서 배열을 직접 수정하면 슬롯과 불일치하므로 저장을 거부한다. 도구/테스트의 기존 유한 월드는 `EnableSlotInventory()`로 명시적으로 이행할 수 있다. 슬롯 모드에서는 `World.Items`를 사용한다.

설치·채굴의 실행 취소는 슬롯 배치까지 복원한다. 다른 슬롯 조작·제작·버리기·줍기를 하면 이전 편집 이력을 비워 수량 복제를 막는다. 비동기 저장은 소유 스레드에서 슬롯·제작·커서·pickup을 분리 복사하며 작업 스레드가 실제 인벤토리를 조회하지 않는다.
