# 처음 실행과 월드 선택 UX

## 조사한 흐름과 적용 기준

마인크래프트 공식 입문 안내는 주 메뉴에서 **Singleplayer → Create New World**로 들어가도록 설명한다. 월드에 바로 스폰되는 이전 BlockCircuit 시작 방식을 타이틀에서 목적을 선택하는 방식으로 바꾼 근거다. [Minecraft 공식 시작 안내](https://www.minecraft.net/en-us/article/how-minecraft)

공식 Java 1.19.4 출시 기록은 월드 생성 화면을 Game·World·More 탭으로 나누고 Ctrl+Tab과 Ctrl+숫자로 이동하는 방식을 설명한다. 이 구조를 참고해 BlockCircuit에서는 **Game**에 이름과 Sandbox 설명을, **World**에 시드·Natural/Classic 지형을 둔다. 지원하는 설정에 맞춘 두 탭이며, Minecraft의 현재 화면 전체를 복제한 것은 아니다. [Minecraft Java 1.19.4 공식 출시 기록](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-19-4)

이번 범위는 처음 켰을 때부터 월드를 선택하고 다시 주 메뉴로 돌아오는 동선이다. BlockCircuit의 블록·조작·저장 형식은 유지한다.

## 사용자 동선

- 처음 실행하면 커서를 사용할 수 있는 타이틀이 나온다. Singleplayer, Multiplayer, Options, Quit 중에서 고른다.
- Singleplayer는 이름 검색과 스크롤이 가능한 월드 목록을 보여 준다. 월드 이름·지형·최근 플레이 시각·시드를 확인하고 Play Selected World, Enter 또는 더블 클릭으로 들어간다. Edit에서 이름 변경과 백업을 하고, Delete는 별도 확인 화면을 거친다.
- 새 월드의 Game 탭에서 최대 64자 이름을 정한다. World 탭에서 시드를 비워 무작위로 만들거나 -2147483648–2147483647 정수를 입력하고, Natural/Classic을 선택한다. Classic은 기존 시작 영역과 그 바깥으로 이어지는 새 지형이다. Ctrl+Tab, Ctrl+1, Ctrl+2로 탭을 바꾼다. 생성하기 전에는 기존 월드를 바꾸지 않으며 같은 이름도 별개의 월드로 만든다.
- 월드 생성·열기 동안 로딩 상태를 표시하고 플레이 입력을 받지 않는다. 성공한 뒤에만 게임 화면과 마우스 시점 조작으로 바뀐다. 실패하면 오류와 함께 이전 선택/생성 화면으로 돌아간다.
- 게임의 Esc 메뉴에서 계속하기·설정·멀티플레이 관리·저장 후 타이틀 복귀를 선택한다. 저장에 실패하면 플레이 중인 월드를 버리지 않는다.
- 타이틀에서 Multiplayer를 고르면 개인 월드를 먼저 열지 않고 IP 접속을 시작할 수 있다. 호스팅은 플레이할 월드를 연 다음 관리한다. 멀티플레이의 세션/소지품 보존 규칙은 [멀티플레이 문서](multiplayer.md)를 따른다.
- 타이틀의 Options는 월드를 생성하거나 불러오지 않고 설정할 수 있다.

빈 목록에서 곧바로 생성 화면으로 들어가는 동작은 BlockCircuit의 선택이다. 취소하면 빈 월드 목록으로 돌아가 다시 만들거나 Back으로 타이틀에 돌아갈 수 있다. 마인크래프트의 모든 버전에서 빈 목록을 건너뛴다고 가정하지 않는다. 타이틀에서는 Tab/아래·위 방향키로 항목을 고르고 Enter/Space로 실행할 수 있다. 텍스트 칸은 Ctrl+A/C/V, 좌우/Home/End, Backspace/Delete를 지원한다.

## 월드 목록과 저장

앱 데이터 루트는 .NET `LocalApplicationData/BlockCircuit`이며 Windows에서는 보통 `%LOCALAPPDATA%\BlockCircuit`다. 새 월드는 루트 아래 `worlds/<GUID>/world.json`과 `world-info.json`을 갖는다. 이름은 화면 표시용이며 경로로 쓰지 않는다. 각 월드는 자신의 블록·슬롯·커서·제작·게스트 기록을 보존한다. 화면·조작 설정과 멀티플레이 접속 프로필은 루트의 `settings.json`, `multiplayer-profile.json`에 따로 둔다.

목록에 들어가는 것만으로 지형을 생성하거나 기존 저장을 다시 쓰지 않는다. Edit에서 Make Backup을 명시적으로 고르면 원래 월드와 최근 플레이 시각을 바꾸지 않고 루트 `backups/`에 단독 복원 가능한 v3 백업을 만든다. 목록의 이름·생성/최근 플레이 시각 같은 설명과 실제 월드 파일은 분리한다. 설명이 손상된 한 월드 때문에 다른 정상 월드를 숨기지 않으며, 가능한 복구는 명시적으로 해당 월드를 열 때 수행한다.

기존 저장 폴더의 `world.json` 또는 복구용 `world.json.bak`는 목록의 기존 월드 항목으로 발견한다. 시작 화면을 열었다는 이유로 원본 JSON·청크를 옮기거나 새 지형으로 바꾸지 않는다. 새 월드는 별도 폴더에 만든다.

월드 제거는 사용자 확인 뒤 해당 월드 파일만 `trash/` 안으로 옮긴다. 이 작업은 다른 월드·앱 설정·접속 프로필을 제거하지 않는다. Trash 복원 전에는 게임을 종료하고 보관한 JSON과 `.chunks/`, `.bak`를 함께 복원해야 한다. 전역 예전 백업은 해당 월드 삭제와 별도로 남긴다.

F6 또는 Esc의 Create New World는 현재 월드 저장을 성공시킨 뒤 별도 생성 화면으로 간다. 새 월드를 만들기 위해 기존 저장을 다른 이름으로 바꾸거나 삭제할 필요가 없다. 명시적 백업은 목록의 Edit에서 만든다. 활성 멀티플레이 중에는 다른 월드 생성을 막는다.

## 검증 범위

`--startup-tests`의 `WorldLibraryTests`는 실제 임시 폴더에서 빈 시작·서로 다른 월드의 생성/수정/재입장·이름/시드·최근 플레이·경로 안전성·손상 항목·기존 파일 발견·복구 저장·백업·되돌릴 수 있는 제거·생성 실패 보존을 검사한다. `StartupFlowTests`는 타이틀과 목록·생성·로딩·복귀의 상태 전환, 로딩 실패, 입장 입력 해제, 텍스트 편집을 검사한다.

Debug/Release 각각 707개 회귀 검사와 11개 OpenGL 모드가 통과했다. `--startup-smoke-test`에서 일반 시작 생성자와 실제 창·세션 핸들러로 37개 항목을 확인했다. 첫 화면·로딩·월드 생성/입장·저장 실패/재시도·타이틀 IP 접속/취소/오류 복귀·GPU 해제를 검증하고 PNG를 열어 최소 960×640 배치를 점검했다. 물리 마우스·키 입력 자동화나 WAN 검증은 아니며 기존 20TPS·인벤토리·멀티플레이 회귀를 유지했다. [실행 로그·화면·한계](validation/startup-ux/README.md)를 따른다. UI는 영문이며 한글 폰트·IME UI는 이번 범위에 포함하지 않았다.
