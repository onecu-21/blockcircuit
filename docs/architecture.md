확장 전 코드의 상태를 기록한다. 현재 Phase 01에서 변경된 20 TPS 시간/물리/입력 계약은 [physics.md](physics.md)를 따른다. 후속 단계는 [roadmap.md](roadmap.md), 측정 원본은 [기준선 기록](baseline/2026-11-04/README.md)을 따른다.

## 런타임과 구성

BlockCircuit.csproj는 C# / net10.0, nullable, implicit usings, unsafe를 사용한다. 외부 패키지는 Raylib-cs 6.1.0 한 개다. Program.cs는 헤드리스 검사·벤치마크 인자를 먼저 처리하며 일반 실행에서는 Game을 만든다. 테스트는 같은 실행 파일의 명령행 모드다.

| 코드 | 현재 책임 |
|---|---|
| Core/Game.cs 및 partial 클래스 | 창, 프레임 루프, 입력/UI, 월드·플레이어·렌더러 수명, 저장 세션 |
| Core/GameClock.cs | 고정 틱, 누적 시간, 보간 비율, 밀린 시간 제한 |
| Physics/ | 입력과 그래픽에서 분리한 플레이어 물리, 축별 swept 충돌, DDA 레이캐스트, 카메라 벽 검사 |
| World.cs 및 World/ | 유한 월드 API, 청크 저장소, 지형, 저장·복원, 편집 이력·백업 |
| BlockCatalog.cs / BlockPalette.cs | byte 블록 ID와 정적 메타데이터, 검색·분류·9칸 퀵바 선택 |
| Circuits/ | 변경 이벤트, 인접 그래프, 연결 집합, 증분 전원 계산 |
| Rendering/ / BlockRenderer.cs | CPU 그리디 메시, 프러스텀 컬링, GPU 캐시, 절차적 atlas·shader |
| SelfTests.cs / Tests/ | 게임 규칙·저장·청크·메시·물리·조작 검사와 CPU 벤치마크 |

## 틱과 물리

현재 실제 게임은 GameClock(60, 8)을 사용한다. 기본 생성자도 60 TPS이며 목표 20 TPS는 Phase 01 작업이다. 스텝은 1/60초, 입력 프레임 시간 상한은 0.25초, 프레임당 최대 실행은 8틱이다. 초과 시간은 DroppedSeconds에 기록하고 Alpha는 남은 틱 비율을 1 미만으로 제공한다.

GameSimulation.CaptureInput은 매 렌더 프레임 마우스 회전을 적용하고 이동/누른 상태를 수집한다. 점프 눌림은 다음 틱까지 보존하고 설치·레버·실행 취소/재실행은 큐에 넣는다. SimulationTick은 물리, 액션, 채굴과 회로 대기를 처리한다. 위치는 이전/현재 발 위치를 보간한다. 메뉴·일시정지·로드에서는 누적 시간과 대기 입력을 초기화한다. 비행 전환과 퀵바 선택은 현재 프레임 입력 경로에서 처리된다.

PlayerBody 기준 상수는 중력 20블록/s², 점프 7블록/s이며 중력을 먼저 적용한다. 수평 이동은 속도 직접 적용으로 관성·마찰·공중 가속도 모델은 없다. 입력 경로의 걷기/달리기/웅크리기 속도는 4/6/1.3블록/s다. Minecraft Java의 정밀한 물리 재현으로 검증된 값은 아니다.

CollisionSystem은 X → Z → Y 순서의 swept 충돌을 해결한다. 반폭 0.29, 서 있는 높이 1.75, 웅크린 높이 1.5, 눈높이 1.62/1.27을 사용한다. 유리는 충돌하고 전선/레버는 충돌하지 않는다. 지상 웅크리기는 지지면을 확인하는 짧은 이동으로 절벽 추락을 막는다. 비행도 벽·바닥·월드 경계와 충돌하며 발 높이 상한은 36이다. VoxelRaycaster는 정규화된 광선의 DDA를 사용하고 CameraRig는 3인칭 카메라의 벽 통과를 제한한다.

## 콘텐츠와 청크

Block : byte가 런타임 ID와 저장 ID를 함께 담당한다. 총 180개 항목 중 공기와 기반암을 제외한 178개가 설치 가능하며 기존 ID 0–9는 고정이다. 문자열 영구 ID, 범용 Registry와 등록/동결 수명주기는 아직 없다.

World의 유효 범위는 X/Z 0–39, Y 0–27이다. 범위 밖 Get은 공기, Set은 무시한다. ChunkManager 자체는 음수 좌표를 지원하지만 World·충돌·카메라·생성·저장 경로는 유한하다.

- Cell은 32비트 정수 좌표이고 플레이어/렌더링은 Vector3 float이다.
- ChunkCoord는 16³ 청크 주소와 floor division/0–15 로컬 좌표를 제공한다. 음수 경계 테스트가 이미 있다. 임의 청크 주소의 Origin 곱셈에는 별도 오버플로 검사가 없다.
- Chunk는 비공기 셀이 있을 때만 4,096바이트 배열을 할당한다. 마지막 블록 제거 시 배열을 해제한다.
- ChunkManager는 희소 딕셔너리와 전역 증가 리비전을 소유한다. 실제 변경은 해당 청크와 기존 면 이웃 메시를 무효화한다. 빈 청크는 제거한다.
- World.Blocks는 저장/호환성용 44,800바이트 평면 스냅샷이다. 반환 배열 변경으로 라이브 상태를 바꿀 수 없다.

리비전은 메시 무효화용이며 저장 Dirty Flag가 아니다. 청크 상태 머신, 청크별 디스크 저장, 작업 취소와 스트리밍은 아직 없다. 컬렉션은 동시 읽기/쓰기를 보장하지 않는다.

WorldGenerator는 시드 기반 노이즈·좌표 해시로 지형/동굴/광석/나무를 생성한다. 현재는 전체 유한 월드를 동기 생성하고 전역 높이 배열과 스폰 평탄화를 사용한다. 새 일반 게임은 시드 2026 자연 지형, new World()는 호환성 검사용 기존 지형/시드 731이 기본이다. 무한 생성에는 경계 연속성과 청크를 가로지르는 나무의 소유권 설계가 필요하다.

## 편집·회로·인벤토리

World는 설치·채굴·레버를 트랜잭션으로 기록하고 EditHistory는 셀 상태와 수량 차이를 최대 128개 보관한다. 재생 전 모든 셀/수량/플레이어 중첩을 검사하므로 거부된 실행 취소는 부분 적용되지 않는다. 저수준 Set의 실제 변경은 충돌하는 이력을 초기화한다.

CircuitSystem은 블록/레버 이벤트 큐, 면 인접 그래프와 연결 집합을 캐시한다. 전원 전환은 해당 집합만 평가하고 부품 편집은 관련 집합을 분할/병합한다. 일반 지형 편집은 회로망을 재계산하지 않는다. 레버 신호는 15, 전선/램프마다 1 감소하고 램프는 종단이다. 전원 변경 셀은 메시를 무효화한다. 생성/로드/공개 상태 직접 수정 뒤에는 Rebuild를 사용한다. 회로 전용 이벤트이며 공개 범용 Event API는 아니다. 예약 틱·방향성 부품·피스톤은 아직 없다.

인벤토리는 블록 ID별 int[180] 수량이다. 시작 시 설치 가능한 블록마다 128개를 지급한다. 9칸 퀵바는 블록 선택 목록이며 아이템 스택 슬롯이 아니다. 36칸 슬롯·스택 제한·제작·드롭 엔티티는 아직 없다.

## 렌더링과 GPU 수명

ChunkMesher는 청크와 1블록 halo를 읽고 숨은 면 제거와 그리디 병합을 수행한다. 재질/방향/텍스처 변형/밝기/투명도/램프 상태가 다른 면은 합치지 않는다. 불투명·반투명 CPU 메시와 작은 회로 모델 좌표를 반환한다. 고정 방향별 밝기와 밝은 발광 재질 외형은 있으나 전파되는 Skylight/Blocklight는 없다.

BlockRenderer.DrawWorld는 렌더링 스레드에서 CPU 메시 생성과 GPU 업로드를 모두 수행한다. 청크 객체 또는 리비전 변경 시 갱신한다. ChunkManager 교체는 전체 캐시 해제, 청크 제거는 다음 그리기에서 해당 캐시 해제를 일으킨다. 현재는 컬링 전에 변경 메시를 만들므로 화면 밖 변경도 CPU 작업을 일으킨다. 거리 컬링은 캐시를 언로드하지 않는다.

ChunkMesh는 위치/UV/색 VBO 세 개와 VAO를 소유한다. 용량 내 변경은 버퍼를 재사용하고 초과 시 2배 용량으로 새 메시를 만든 뒤 기존 메시를 해제한다. 빈 메시 변경은 활성 정점 수만 0으로 만들고 용량은 유지한다. Dispose는 중복 호출에 안전하다. 모든 GPU 작업은 렌더링 스레드 계약이며 런타임 스레드 검사로 강제하지는 않는다.

종료 시 렌더러는 캐시, material 맵 메모리, 공유 shader와 atlas를 각각 해제한다. Game은 finally에서 렌더러를 해제한 뒤 창/GL 컨텍스트를 닫는다. 초기화 실패에도 atlas/shader 정리 경로가 있다. 반투명 청크는 뒤에서 앞으로 정렬하지만 청크 내부 면 정렬은 없어 겹친 유리의 표시에는 한계가 있다. 이번 Windows OpenGL 엔진 스모크는 종료 후 자원 해제를 확인했다.

## 저장과 마이그레이션

World.SaveData는 System.Text.Json IncludeFields로 단일 JSON에 저장한다.

| 필드 | 현재 계약 |
|---|---|
| Version | 읽기 1/2, 쓰기 2 |
| Blocks | byte[44800], JSON Base64 문자열. 인덱스 (y * 40 + z) * 40 + x |
| Switches | 켜진 레버 셀 배열. Power는 로드 뒤 재계산 |
| Inventory | v1 10개, v2 180개 정수 |
| Position / Yaw / Pitch | 유한 값과 위치 경계를 검증. pitch 제한 |
| Seed / TerrainVersion | 선택적 메타데이터. 누락 시 731/0. 지형 버전 0/1 허용 |

v1은 블록 ID 0–9만 허용한다. 로드 시 기존 셀·레버·수량을 보존하고 새 블록 170종에 초기 수량을 채운다. v2 수량은 그대로 복원한다. 잘못된 배열/ID/수량/위치/버전은 활성 월드 교체 전에 거부한다. 새 청크 저장소를 준비한 뒤 교체하고 회로/이력을 갱신한다. 알 수 없는 모드 블록의 문자열 ID나 원본 데이터 보존은 현재 없다.

저장은 path.tmp를 먼저 쓴 후 File.Move(overwrite: true)로 교체한다. 부분 JSON을 직접 덮어쓰는 위험은 줄이지만 디렉터리 fsync, 일반 저장 백업이나 손상 파일 자동 복구를 구현한 것은 아니다. WorldSession.Create는 새 월드 교체 전에 기존 월드를 backups/world-<UTC>-<GUID>.json으로 저장한다. Phase 02/03의 새 형식 이행에는 구형 원본 백업과 재시도 가능한 마이그레이션이 필요하다.

게임 데이터는 LocalApplicationData/BlockCircuit에 저장한다. 별도 settings.json v1은 FPS/FOV/감도/거리/퀵바/선택 슬롯을 저장하고 8칸 퀵바를 9칸으로 이행한다. 잘못된 설정은 기본값과 경고로 처리한다.

## 검증과 남은 격차

기존 5개 헤드리스 명령의 총 229개 판정을 Debug/Release 각각 통과했다. 기존 7개 Release 그래픽 모드도 Windows에서 종료 코드 0으로 실행했다. CPU 벤치마크와 그래픽 원본은 기준선 폴더에 분리했다. CPU 시간/관리 할당은 FPS·P95/P99·상주 메모리·GPU 메모리·장시간 안정성 측정이 아니다.

CI build.yml은 Ubuntu 24.04/Windows의 .NET 10 Release 헤드리스 검사, Linux Xvfb/Mesa 그래픽 검사와 Windows self-contained 배포를 구성한다. 이는 구성 검토이며 이번에 원격 CI를 실행한 결과는 아니다. 로컬 출력은 bin/x64/<Configuration>/net10.0이었다. 검증 도구는 실제 출력 경로를 확인해야 한다.

주요 확장 경계는 60→20 TPS와 물리 규칙, byte→Registry ID, 유한 World→청크 저장/스트리밍, 슬롯 인벤토리/제작, 전파 조명/시간, 유체, 고급 회로, 엔티티/AI와 날씨다. 기존 기능과 저장 호환성을 유지하며 [단계 순서](roadmap.md)에 따라 보강한다.
