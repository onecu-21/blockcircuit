# 이벤트 기반 낙하 블록

기본 블록 중 모래(Sand), 붉은 모래(RedSand), 자갈(Gravel)에 중력을 적용한다. [Minecraft 공식 모래 소개](https://www.minecraft.net/zh-hant/article/block-week-sand)의 지지대가 없으면 떨어지는 성질을 참고한다. 아래 상수와 처리 예산은 BlockCircuit에서 채택한 낙하 프로필이며 원작 전체 낙하 규칙과의 비트 단위 일치를 주장하지 않는다.

## Registry 속성과 틱

BlockInfo.AffectedByGravity의 기본값은 false다. 기본 Registry 등록에서 위 세 종류를 true로 지정한다. 모드 블록도 같은 속성으로 낙하를 선택할 수 있으며, 영구 ID와 JSON 블록 상태를 이동·저장·복원에 함께 보존한다.

World.FallingBlocks는 FallingBlockSystem이다. World.Tick의 고정 20 TPS에서 진행하고 렌더 FPS로 물리 시간을 계산하지 않는다. 블록 변경은 해당 셀과 바로 위 셀을 후보로 등록하며, 청크 도착 시 그 안의 후보를 등록한다. 매 틱 모든 상주 블록을 순회하지 않는다. 후보는 HashSet과 큐로 중복을 제거한다.

| 항목 | 값/기본 예산 |
|---|---:|
| 중력 | 처리 틱마다 수직 속도에서 0.04 block/tick 감소 |
| 수직 감쇠 | 이동 뒤 0.98배 |
| 최대 하강 속도 | 3.92 block/tick |
| 활성 낙하 개수 상한 | 4,096개 |
| 대기 후보 개수 상한 | 1,000,000개 |
| MaxScheduledChecksPerTick | 512개 후보 검사 |
| MaxActiveUpdatesPerTick | 256개 활성 낙하 갱신 |

수직 계산은 속도 감소 → 경로 검사·이동 → 감쇠 순서다. 속도의 단위는 초당 거리가 아닌 50 ms 처리 틱의 이동량이다. 활성 개수가 예산보다 많으면 순환 인덱스로 후속 틱에 분산하며, 대량 부하에서는 각 블록의 진행이 지연될 수 있다.

## 시작·이동·착지

아래 셀이 통과 가능하면 원래 셀에서 낙하 상태로 옮긴다. FallingBlock에는 Id, PersistentId, 런타임 Block, Position, PreviousPosition, VelocityY와 Data가 있다. X/Z는 셀 중심이고 Y는 블록의 바닥 높이다. 이전/현재 위치는 렌더 보간에 사용할 수 있다.

공기·전선·레버를 통과 가능한 셀로 취급한다. 하강 경로의 각 셀을 검사하여 빠른 낙하가 한 칸 받침을 통과하지 않게 한다. 같은 열의 활성 낙하끼리도 겹치지 않도록 아래 블록의 윗면을 지지면으로 취급한다.

착지 칸이 비어 있어야 정적 블록으로 되돌린다. 동시에 설치된 블록은 덮어쓰지 않고 제한된 위쪽 범위에서 착지를 재시도한다. 착지 칸에 전선·레버가 있으면 기존 채굴 경로로 회수하여 수량과 회로 상태를 갱신한다. World의 블록 변경 경로를 사용해 회로와 청크 메시·저장 Dirty를 갱신한다.

호스트는 CanLand(Cell)로 플레이어와 겹치는 착지를 지연시킬 수 있다. World와의 이동은 인벤토리에서 재료를 소비하거나 새 블록 수량을 만들어내는 제작 작업이 아니다.

이벤트 리스너가 이동 중 저장해도 하나의 표현만 보도록, 출발 시에는 활성 상태를 먼저 만든 뒤 원래 블록을 제거한다. 착지 시에는 활성 상태에서 제거하고 블록·payload를 설치한 뒤 변경 이벤트를 통지한다. 편집 트랜잭션이나 실행 취소가 처리 중일 때의 중복 이동도 거부한다.

## 청크 경계와 보류

출발·하강·착지 셀의 가용성을 확인한다. 미로딩 열에 들어가거나 알 수 없는 모드 블록을 다른 블록으로 바꾸면서 진행하지 않는다. 필요한 열이 준비되지 않았거나 Registry에 원래 ID가 없으면 상태를 보존하고 기다린다. 모드를 다시 등록한 월드로 불러오면 원래 ID와 데이터로 진행할 수 있다.

PinnedChunks는 현재 위치와 아래 진행 구간을 포함한다. WorldStreamer는 이 열을 활성 낙하가 끝나기 전에 해제하지 않는다. 청크 도착 시 경계 후보를 다시 등록하므로 기다리던 블록이 진행할 수 있다. Y=0 아래에는 보존용 바닥을 적용해 블록이 무한한 빈 공간으로 사라지지 않게 한다.

낙하 좌표의 실용 범위는 X/Z 약 ±1,000,000블록이다. 이 시스템의 좌표 검증과 실제 플레이어의 이동·설치 높이 제한은 별도이며, 현재 새 지형의 생성 높이는 [streaming.md](streaming.md)를 따른다.

## 저장과 복원

FallingBlockSaveState v1에는 Active와 Pending이 있다. 활성 레코드는 GUID, 영구 문자열 ID, 현재/이전 위치, 속도와 복제한 JSON 데이터를 저장한다. 대기 후보 셀도 함께 보존한다.

v4 월드 매니페스트와 v3 ExportSnapshot은 이 상태를 포함한다. 복원 전에 버전·개수·중복 ID·좌표·유한한 속도·같은 열의 겹침·중복 대기 셀을 검사한다. 실패하면 활성 월드를 바꾸지 않는다. 미설치 모드 ID는 보존하고 정적 블록으로 강제 변환하지 않는다.

정적 원본·활성 상태·착지 결과 사이의 보존과, 저장 도중 수정·언로드·재진입은 회귀 검사로 확인해야 한다. 실행 결과와 비용은 최종 검증 기록을 따른다.

## 현재 범위

이 구현은 블록 낙하를 위한 전용 상태 시스템이다. Phase 09의 범용 엔티티·아이템 드롭·체력 시스템을 구현한 것은 아니다. 낙하 피해·질식 피해·도구별 드롭·물과 용암 상호작용은 포함하지 않는다. 플레이어가 착지 위치를 막으면 피해를 적용하는 대신 대기한다.

실제 게임에서 보간된 낙하 위치를 기존 블록 아틀라스로 그린다. 낙하 중인 열은 준비된 지형에서 핀으로 유지하며, 사라진 모드나 지원 높이 밖 상태는 데이터를 보존한 채 대기한다. 상세 검증·CPU 측정은 [Phase04 검증 기록](validation/phase04/README.md)을 따른다.

대량 낙하에서는 기본 활성 갱신 예산256개를 순환하므로 개별 블록의 진행이 지연될 수 있다. 512개 부하에서는117틱에 전부 착지했으며 매 이벤트마다 수량 보존을 확인했다. 일반 엔티티 생명주기·압사 피해·아이템 드롭 엔티티는 후속 Phase09 범위다.
